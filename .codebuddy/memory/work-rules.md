# 编码铁律与测试要求

> 作者：袁燕 | 创建：2026-08-10 | 跨会话生效

## 1. 修改前三轮分析（强制）
- 第一轮 需求分析：理解真实诉求与隐含需求
- 第二/三轮 影响分析：①影响哪些文件/模块 ②是否破坏现有功能 ③同类问题是否别处也存在（举一反三）
- 禁止直接跳入编码，先分析后动手

## 2. 验证铁律（修改后必须实跑验证才结束）
- 前端拆分：用 Node 注入 DOM stub 实跑渲染函数（如 Pages.base()），不靠 node --check（语法对≠运行不崩）
- 预览：preview_url 打开实际查看渲染（可见性/触屏/四色一致）再回复
- 后端：curl 真实 HTTP 验证 CRUD 闭环 + 400 校验
- 禁止只编译/语法通过就交差

## 3. 触屏优化标准（继承智能柜）
- 按钮 ≥48px，圆角 12-14px，字体 16-18px
- 输入框高度 48px，字体 16px
- 统一表单控件，颜色对比清晰

## 4. 分层与解耦（继承智能柜 P18）
- 前端绝不直连 DB；取数只走 Api 封装（HTTP+JSON）
- 前端按页面解耦：js/pages/<id>.js 各管各页，css 拆 common.css + css/pages/<id>.css
- 字段统一驼峰（reqId）；ORM/DB 内部蛇形（req_id）（P13）
- 路由不降级：无效参数返回明确 400，不静默返回错误数据（P10）

## 5. 记忆铁律（袁总第1条指令，2026-08-13 强化）
- 每次对话结束前必须写 session-log.md（做了什么 + 踩的所有坑），写完记忆才能向袁总汇报；这是每轮工作的收尾动作，不是可选项
- 进度有变化时同步更新 session-init.md「当前进度」；踩新坑写 qc-lessons.md
- 文件：session-init.md / project-context.md / work-rules.md / qc-lessons.md / session-log.md / user-profile.md
- 血泪教训：08-11/08-12 两轮 SVN 集成做完没写记忆，导致袁总下次开会话以为历史全丢，凭文件时间戳才补回来

## 6. 数据对标铁律
- 示例数据优先用 R105 真实值，禁止凭空编造；对标表格全对标 + 支持增删改查

## 7. 脏数据铁律（继承智能柜）
- 代码层绝不写数据修复函数；不一致直接用 MySQL 命令修复
