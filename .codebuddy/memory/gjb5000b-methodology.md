## 第一章：GJB5000B 体系认知

### 1.1 体系是什么

GJB5000B 是军用软件研制能力成熟度模型，全称《军用软件能力成熟度模型》。它定义了软件研制过程中需要达到的 22 个过程域（PA），覆盖项目管理、工程、支持、组织管理四大类。

**核心目标**：通过标准化过程域管理，确保军用软件质量、进度、成本可控，满足 GJB 体系要求。

### 1.2 平台覆盖的过程域

| 过程域 | 缩写 | 核心功能 | 关键模板 |
|--------|------|----------|----------|
| 项目策划 | PP | 估算、风险、资源、进度表、利益相关方 | A3/A5/A10/A11/A14/A16/A79 |
| 项目监控 | PMC | 阶段监控、周报/双周报、问题跟踪、偏差分析 | A16/A20/A21/A22/A23/A17 |

| 测试验证 | VER/VAL | 测试计划/说明/报告 | 测试计划/测试说明/测试报告 |

| 结项管理 | END | 结项报告、数据回流 | 结项报告 |

### 1.3 数据血缘全景

**核心数据流**：
```
基础数据配置中心（BASE_DICT + BASE_SEL）
    ↓
PP 汇聚模型（估算/风险/资源/相关方/进度）
    ↓
PMC 阶段监控（偏差比对/问题跟踪/风险跟踪）
    ↓
MA 测量分析（8类基础数据自动汇聚）
    ↓
组织过程资产库（模板优化/CBB/经验）
    ↓
组织测量库（组织级数据）
```

**关键数据血缘关系**：
- 估算数据 → PP 汇聚 → PMC 偏差比对
- 风险数据 → PP 录入 → PMC 风险跟踪
- 进度数据 → PP 进度表 → PMC 偏差分析 → A32 进度测量
- 周报工作量 → A32 工作量测量
- 代码检视缺陷 → A27 不符合项 → A26 质量保证报告
- 测试缺陷 → A32 测试缺陷统计
- 配置项变更 → A60/A61 → A26/A19 配置状态

## 第二章：效率提升方法论

### 2.1 基础数据配置中心模式

**核心思想**：所有页面的基础数据（风险项/资源项/相关方/外部承诺/估算模块）统一收敛到「基础数据配置中心」，采用多选字典池模式。

**实现方式**：
- `BASE_DICT`：预置可选项（全局字典）
- `BASE_SEL`：按项目存储已选（项目级选择）
- 用户「尽可能选、少写」，减少手工录入

**效率提升点**：
- 避免各过程域重复录入相同数据
- 数据一致性保证（一处修改，全局生效）
- 减少录入错误

### 2.2 估算按模块汇聚

**核心思想**：估算按模块填写（规模 KLOC / 工作量 人时 / 工期 天），汇总自动汇入 PP 汇聚模型。

**实现方式**：
- 每个模块独立录入估算数据
- 系统自动汇总到 PP 汇聚模型
- 各过程域（PP/PMC/REV/OUT）只从字典池「选」数据并标注取数来源

**效率提升点**：
- 避免各过程域空白手填
- 自动汇聚减少人工计算
- 数据可追溯（标注取数来源）

### 2.3 内联可编辑表格模式

**核心思想**：所有表格支持内联编辑，无需弹窗即可修改数据。

**实现方式**：
- `OUTPUT_FIELDS`：定义表格字段
- `OUTPUT_SAMPLE`：预置样例数据
- `OUTPUT_DATA`：仓储机制，支持增删改查
- 内联 input 直接编辑，保存按钮批量提交

**效率提升点**：
- 减少弹窗操作，提升录入效率
- 所见即所得，降低认知负担
- 批量操作支持

### 2.4 双周任务表模式

**核心思想**：从本阶段进度表任务生成双周任务表，支持从 SVN 同步/平台修改/同步回 SVN 三向操作。

**实现方式**：
- 从进度表自动提取本阶段任务
- 支持内联编辑修改
- `⬇ 从SVN同步`：从受控库拉取
- `⬆ 同步回SVN`：修改后自动同步

**效率提升点**：
- 避免双周任务与进度表数据不一致
- SVN 双向同步，保持受控库与平台一致
- 按阶段独立存储，切换阶段互不干扰

### 2.5 阶段切换机制

**核心思想**：阶段完成校验 + 切换按钮 + 下一阶段初始化。

**实现方式**：
- 5 项完成检查勾选（进度表/风险/问题/周报/阶段报告）
- 切换按钮「✓ 阶段完成·切换到下一阶段」
- 切换后自动初始化下一阶段数据

**效率提升点**：
- 明确阶段边界，避免遗漏
- 自动初始化减少手工准备
- 记录切换日志，可追溯

## 第三章：MPP 技能提取方法

### 3.1 什么是 MPP

MPP（Measurement, Process, Product）是 GJB5000B 体系中的核心概念：
- **Measurement（测量）**：通过 8 类基础数据量化过程与产品质量
- **Process（过程）**：各过程域的标准流程和模板
- **Product（产品）**：各阶段产出的工作产品

### 3.2 技能提取流程

**第一步：识别过程域**
- 从 R105 体系文档中识别当前项目涉及的过程域
- 确定每个过程域的输入/输出/角色/模板

**第二步：提取测量项**
- 从 A32 测量分析报告中提取 8 类基础数据
- 工作量/进度偏差/需求变化/缺陷密度/不符合项/测试缺陷/配置项变更/评审问题

**第三步：提取模板技能**
- 从体系/模板/目录提取标准模板
- 从 R105 对应目录提取真实样例
- 对标真实数据，确保字段/格式一致

**第四步：建立数据血缘**
- 确定数据从哪里来（取数来源）
- 确定数据到哪里去（数据流向）
- 标注数据血缘关系

**第五步：平台化封装**
- 将提取的技能封装为平台功能模块
- 每个模块支持增删改查
- 模块间数据自动流转

### 3.3 实践案例：评审问题提取

**步骤**：
1. 从 R105 质量保证/目录提取评审报告 docx
2. 用 PowerShell 解压 docx 为 zip，正则解析 word/document.xml 提取表格
3. 确认评审问题表 6 列结构：序号/问题描述及处理措施/责任人/验证人/约定解决日期/问题跟踪及验证情况
4. 在平台中创建 `REVIEW_ISSUE_FIELDS` 仓储
5. 预置 5 阶段样例数据
6. 实现增删改查 + SVN 同步

### 3.4 实践案例：风险表提取

**步骤**：
1. 从 A11 风险管理表提取字段：风险项/风险等级/影响等级/控制措施/应对措施/预防措施/机遇/阶段/责任人
2. 在平台中创建 `PMC_RISK_WIDGET` 仓储
3. 预置样例数据
4. 实现增删改查
5. 优化列宽（table-layout:fixed + word-break:break-word）确保长文本完整显示

## 第四章：平台设计原则

### 4.1 架构原则

1. **数据驱动**：所有功能模块基于数据仓储，数据变化驱动 UI 更新
2. **模块化**：每个过程域独立模块，模块间通过数据血缘关联
3. **可扩展**：新增过程域只需定义 FIELDS/SAMPLE/DATA 三件套
4. **可追溯**：所有数据标注取数来源，支持数据血缘追溯

### 4.2 UI 设计原则

1. **小米极简美学**：功能优先但不忽视美学
2. **四色体系**：主色 #1a73e8（蓝）/ 成功 #52c41a（绿）/ 警告 #faad14（黄）/ 危险 #ff4d4f（红）
3. **触屏优化**：按钮 ≥48px、圆角 12px、字体 16-18px
4. **内联编辑**：表格内直接编辑，减少弹窗
5. **SVG 矢量**：架构图/流程图用 Web(SVG) 绘制，不用 matplotlib

### 4.3 数据对标原则

1. **R105 真实数据对标**：所有表格字段/格式与 R105 体系文档 1:1 一致
2. **真实样例优先**：数据样例优先使用 R105 真实数据做仿真示例
3. **增删改查全覆盖**：所有对标表格都具备增删改查能力
4. **SVN 双向同步**：关键数据支持从 SVN 同步和同步回 SVN

### 4.4 阶段管理原则

1. **阶段完成校验**：切换阶段前检查 5 项完成状态
2. **数据隔离**：各阶段数据独立存储，切换阶段互不干扰
3. **自动初始化**：切换后自动初始化下一阶段数据
4. **日志记录**：所有阶段切换操作记录日志

### 4.5 技术栈铁律（2026-08-08 袁总确认，跨会话生效）

GJB5000B 平台总体方案及实际工程，技术栈表述必须统一，严禁混用错误栈：

1. **后端**：Python 3 + FastAPI/Flask（严禁 Node.js / Express）
2. **前端**：Web(HTML + SVG 原生)，单文件页面、浏览器直接开、无第三方框架依赖（严禁 Vue / React / Angular）
3. **版本管理**：SVN 命令行（svn import/commit 或 pysvn），三库（开发库/受控库/产品库）流程（沿用现有配置管理）
4. **数据库**：SQLite / MySQL / 达梦 DM8 可选，统一 Python ORM 访问；本地轻量用 SQLite 免安装
5. **文档生成**：Python 锚点模板引擎（python-docx / openpyxl），`{{锚点}}` 占位符取数替换，不经 Node.js 文档库
6. **报告生成即锚点替换**：每份 GJB5000B 模板（A1~A83）在 Word/Excel 中以 `{{锚点}}` 占位，Python 读统一数据库真实值一键填充，R1~R19 校验后 SVN 提交

**血泪教训**：总体方案 V7.1/主文件第8章曾被写成"Vue3 + Node.js + MySQL"，领导直接指出"互动了个寂寞"。凡方案提到实现框架，必须套本条铁律。

## 第五章：实践总结与教训

### 5.1 成功实践

1. **基础数据配置中心**：大幅减少重复录入，提升数据一致性
2. **内联可编辑表格**：提升录入效率 3 倍以上
3. **双周任务表**：实现进度表与双周任务自动同步
4. **阶段切换机制**：明确阶段边界，避免遗漏
5. **评审问题在线录入**：替代纸质评审报告，提升跟踪效率

### 5.2 踩过的坑

1. **列宽不够导致内容截断**：风险表/进度表列宽需 table-layout:fixed + word-break:break-word
2. **数据不一致**：各过程域独立录入导致数据不一致 → 统一到基础数据配置中心
3. **SVN 同步冲突**：平台修改与 SVN 修改冲突 → 建立双向同步机制
4. **阶段切换遗漏**：切换阶段时忘记初始化下一阶段 → 建立完成校验+自动初始化
5. **字段命名不一致**：前后端字段命名不一致 → 统一命名规范
6. **docx 章节号补丁叠加错位（2026-08-08 血泪）**：多次独立脚本改章标题/小节号，每次基于"假设的上次结果"定位 marker，导致章号整体少1、小节号前缀与章号不符、中文章号与阿拉伯章号混用。正确做法：每次修改前先 `dump_chaps.py` 确认磁盘真实状态，一次性基于真实状态写最终修复脚本，禁止脚本叠跑。章节号修正用 `re.compile(r'(?<![0-9\.])(%d)\.(\d+)')` 在区间内平移小节号前缀。
7. **docx 被 WPS 占用无法覆盖（2026-08-08）**：袁总用 WPS 打开 docx 时，文件被 `wps.exe` 独占，Python `shutil.copy` / `zipfile 'w'` 写回报 PermissionError，且 WPS 守护进程 `wpscloudsvr.exe` 会自动重启 `wps.exe`。定位用 Sysinternals `handle.exe -accepteula <文件路径>` 找到 pid（如 wps.exe pid 20344）；覆盖前先 `taskkill /F /IM wps.exe` 且 `taskkill /F /IM wpscloudsvr.exe` 防重启，再用 Python 复制。注意 PowerShell 脚本里中文路径会因编码乱码导致复制失败，必须用 Python（无编码问题）执行复制。
8. **docx 章标题文字被拆分**：Word/WPS 打开后常把"第X章"拆成多个 `<w:t>` run，导致连续字符串 `find` 匹配不到；定位段落须用 `xml.rfind('<w:p', 0, xml.find(关键字))` 找段落起点，再合并该段落所有 `<w:t>` 文本校验。
